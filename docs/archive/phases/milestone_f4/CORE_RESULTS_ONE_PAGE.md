# 项目阶段核心成果（一页版）

## 已完成的主链路

```text
公开来源 → skill提炼 → 60题生产
→ 30题×4模型真实执行
→ 8题人工式诊断
→ 8题整体编辑与独立复核
```

| 环节 | 核心结果 |
| --- | --- |
| 正式生产 | 60/60 candidate-ready，三个 motif 各20题 |
| 四模型评测 | 120/120执行完成，116份有效交付物；强弱模型平均分存在清晰差异 |
| 深入诊断 | 8/8发现候选合同或rubric问题，说明旧结构门禁不等于整体有效 |
| 整体修订 | Terra编辑、程序重算、Luna盲解；8/8通过 |
| 三类修复 | 删除虚构余额、补齐三单状态规则、增加就餐人数 |
| Rubric | 从0条独立fact-check改为70%事实权重 |
| 成本 | 26次Tuzi请求，约¥0.98 |

## 当前最重要结论

系统已经证明可以批量造任务，但也证明“每个模块结构正确”不等于“整道任务语义正确”。更合理的下一代架构是：

```text
LLM负责整体设计和编辑
程序负责来源、真值重算、隔离、去重、版本和成本治理
独立模型或人类负责抽查
```

当前不声称这些任务已经证明训练有效，也不声称形成权威 benchmark。
