## 方法开发与冻结迁移周期

用户已批准独立方法研究周期，入口为 [run_r10_task_method_pilot.py](../../Test/run_r10_task_method_pilot.py)。本轮可自主实现、排错和继续既定独立样例，非无限扩题授权。宏观状态仅记概要。

固定 1 个采购开发世界、4 个冻结验证世界（价格、验收、审计、审计）；每题依次生成、挖掘、监督/rubric 编译、独立复核。Sol high 用于生成/编译，官方 DeepSeek V4 Pro max 用于挖掘/复核。验证中首个通过检查的采购、审计题各一次同配置原生 Codex Sol high 试做，未通过则跳过；它不是 Stirrup 模型比较，不启动评分。

硬上限为 24 个会话尝试（20 个生产阶段、2 个试做、2 个技术恢复），单并发，每会话不超过 1800 秒。首次正式调用起计 43200 秒，传输、检查和修复均占用剩余时间；跳过不产生扩题额度。请求数、token、可得费用按 native 记录实际值，无金额硬上限。认证、隔离、未解释指纹变化或总预算故障停止整个范围；语义失败保留并跳过依赖阶段，其他独立题继续。仅明确在语义开始前失败的临时技术故障允许同阶段一次恢复，最多两次；不重抽已开始、超时或低质量的语义会话。

在 taskgenerator Python 环境执行 `prepare --run-id <新标识> --phase development`，拒绝覆盖。执行前完成针对性/全量测试、秘密/diff/链接检查，把代码指纹和验证证据登记到该 ignored 目录的 `readiness.json`。`execute --run-id <标识> --phase development` 复用旧固定依赖层，仅校验身份并做无凭据断网 smoke；不下载依赖、不重建镜像、不增加付费探针。输入只读挂载，原始输出与程序派生产物分开存放。

依赖来源可以用 `--dependency-lock <lock.json>` 与 `--dependency-remote <本机服务器数据目录>` 显式传入，复做不需要读取旧任务或旧 scope。默认值只复用已经验证的依赖层；仍校验固定包版本、wheel/安装文件哈希和镜像。通用修订保存在 [task_method_clarification_v2.md](../../data/r10/task_method_clarification_v2.md)，不含开发题事实。

开发结束后，只写一次通用方法 amendment，不含具体任务事实或诊断答案。用 `prepare --run-id <标识> --phase validation --amendment <通用说明文件>` 保存新方法、代码快照及开发证据哈希；补齐与当前代码匹配的 readiness 后执行同一入口的 validation 阶段。四个验证世界共享冻结提示词，不能中途按结果改方法或修题。`status` 和 `report` 只读本地已有状态。

开发阶段的 Miner 可以引用明确提供的公开角色/触发背景作为挖掘依据；这不放宽 rubric 的候选可见依据规则。已正常返回的 Miner 原稿被控制器误拒此引用时，`prepare --phase development --recover-controller` 仅接受这一明确边界：保存首次停止 receipt 与原代码，离线复验同一原稿，绑定修复代码和原始哈希，再执行尚未开始的阶段。原会话状态与首次失败不改写，deadline 不重置，不产生重跑模型调用；其他已开始或终结语义会话不接受此入口。

验证阶段先完成四个位置并停在 `validation_review_complete`。当前研究者自主只读核查实际材料及返回意见，在 ignored `admission_review.json` 逐位置记录 status 与含路径、locator、observation 的 findings；只使用既定质量维度。专业分歧可以保留为 issue/uncertain，不能将未通过的模型结果提升为通过。随后 `execute --phase trials` 沿用 validation 冻结与原 deadline，导出通过包并按固定领域顺序选择最多两次试做，不新增预算或调用评分器。该检查不把验证诊断反馈给冻结生成流程。鉴权失败仅从失败的 transport/error 事件判断，业务正文中的“unauthorized”不属于 Provider 故障。

每题候选要求、交付路径、监督和 Rubric V2 必须相互追溯；不沿用旧监督编译器固定条目配额。独立复核和控制器引用有效性分开解释。通过题仅导出内部 GDPval 形状副本，原 rubric 完整保留，Solver 不读取含 rubric 的 dataset row。程序仅判结构、来源路径、交付和一致性，所有职业质量为 provisional / LLM-proxy。

Miner 的依据只能来自当时已挂载的输入，不能引用未来派生的题干或交付合同。既有 Rubric V2 对交付结构路径的例外以 `decision_id == deliverable_structure` 判定，仅把 criterion_id 命名为 deliverable_structure 不符合该例外。这类输出合同拒绝须与控制器误解析、Provider 故障、专业复核未通过分开记录；已开始语义会话的失败原稿不因澄清字段而重抽。未到达的复核没有专业 pass/fail 结论。

收尾汇总所有固定位置及跳过原因，核对原始/派生/内部包哈希与 rubric 语义，并检查阶段输入和服务器停止状态。没有领域合格题则跳过该领域试做，不补位。预算余额不授权下一批；保留未实施的方法建议后停止。

用户暂停时先核实远端容器和本地控制器状态，保留已经自然完成的 receipt，不改写为中断。恢复先读暂停记录与首次结果；模型阶段已结束时仅收尾已有产物，不重新执行终结会话。暂停不重置总时钟，离线收尾耗时与正式模型阶段耗时分别报告。

## Agent 自主工厂入口

新增 [run_r10_agent_factory_pilot.py](../../Test/run_r10_agent_factory_pilot.py) 的 `prepare / execute / status / stop / report --run-id <新标识>`。准备只创建独立 ignored 范围，拒绝覆盖；沿用固定镜像及依赖，可用 `--dependency-lock` 和 `--dependency-remote` 指定同一锁定环境。正式运行前将定向/完整回归及秘密/diff/链接检查写入该范围的 readiness.json，包含 `tests_passed` 与匹配 scope 的 `code_hashes`；环境检查和工具联通须在任何模型调用前完成。

此 scope 仅含一个全新采购开发世界，Sol high 用于世界/编译/试做，官方 DeepSeek Pro max 用于挖掘/咨询/终审。最多 12 次启动或续轮，生产及技术恢复共占前 10 次额度，另保留终审和试做各一次；6 小时总时钟不重置，每次最多 30 分钟，生产保留后续最多 60 分钟。额度代表进程启动/续轮，不代表后端请求数。没有合格版本就跳过保留阶段，不补抽。

Agent 通过 `factory-tools` 命令提交 JSON 调用：inspect/check/render 查询实际文件及合同，save-process 保存过程版本，snapshot/diff 保存与比较草稿，consult/handoff/submit 请求调度。调用请求后当前会话正常结束，控制器再执行咨询或交接；同角色仅用明确 ID 续轮。咨询者独立只读；世界咨询不接收可能包含隐藏事实的自由提问，统一从候选记录独立阅读。新业务材料须绑定先保存的过程版本；候选文件改变即失效旧挖掘及监督。历史快照由容器外 Unix socket 服务保存，Agent 不挂载快照目录。

交接说明只留运行证据，不作为下游提示词或 feedback.json。任何返回 Miner 的交接都开启新会话；绑定当前快照的 Miner 自身咨询续轮除外。反馈必须通过角色、来源及快照门槛，未绑定反馈在文件准备和模型启动前拒绝。文件未越界不代表消息未越界，收尾还须检查反馈与会话历史。发现隔离故障时先停止当前 scope，保留原始终止 receipt，另写原因说明；离线修复与新代码指纹另记，不改写旧运行输入或启动新样例。

`consult/handoff/submit` 自动检查当前合同，错误通过工具 JSON 返回，修好后在原会话重新调用工具；这不构成新模型启动。`handoff target=stop` 仅需 reason。收到咨询后，作者对每个 finding 用 `record-disposition` 提交 request_id、finding_id、snapshot、decision（accept/partial/reject）、reason 及 evidence（area、path、locator）；编号由反馈与 help 返回。先保存处理后的快照，再登记意见处理。再次修改文件后须对新快照更新记录；没有缺陷不强制改文件。终审不读取这些处理记录。

启动校验还包含 scope/角色/父版本绑定的明确会话身份与存储路径。最终提交要求三个有效版本的合同检查和适用咨询处理均闭合，不接受旧版检查。实现迭代先通过完整控制器的无模型夹具、定向与 `pytest tests` 回归，以及固定镜像断网无凭据工具检查，再冻结新范围。原生语义失败或隔离故障后只能离线收尾，不以修复代码继续冻结 scope，也不自动新建实验。结构检查、专业终审、试做交付和执行完成分别报告。

咨询、终审和试做角色查询 `schema` 后，在正常结束前调用 `factory-tools finish`。该工具执行当前输出检查，成功后登记文件哈希；控制器收集时拒绝未 finish 或之后改动的输出。复核 finding 的 `path` 必须是清单中的一个完整文件路径，多来源使用多条 finding；错误明确定位到 `review.json checks[i].findings[j].path`。工具纠错仍在同一次原生会话内，不增加会话额度，也不能修改已提交的生产文件。已终结原稿中的合写、缩写或目录引用不自动扩展、改写或转为准入；保留原始 pass 文本与结构拒绝的区别。

`stop` 仅停止当前 scope 的容器。正常轮间暂停可以显式继续；已经开始而异常终止的语义会话记 incomplete，不以续轮重抽。已正常结束的计划性交接不是重试。只有模型启动前明确的临时传输失败允许一次恢复，计入生产额度；认证、隔离或指纹异常停止。最终提交后禁止修改，只安排一次新会话终审，通过后才试做与内部 GDPval 兼容导出，不评分。所有运行介入与不理想结果保留，结束后不扩题。

## 有限跨场景批次入口

自主工厂入口增加与 `--run-id` 互斥的 `--batch-id <新标识>`，仍使用 `prepare / execute / status / stop / report`。准备时传入 `--source-bundle <目录>`，其中 `verified_sources.json` 对每个显式来源记录实际保存文件、SHA、URL、访问日期、已核实摘要及适用限制；只按摘要范围解释verified，不代表全文或现行法律意见。旧目录页未重现的归因必须明确限定，不能照抄旧摘要为新验证结论。包内原始检索记录仅作运行证据；角色只接收对应职业的方法摘要和来源说明，不接收旧题目或答案。

执行先跑开发题。终审pass且试做有效后，入口停在 `awaiting_readonly_review`，由已授权主对话只读核对并在该子scope写一次 `researcher_review.json`，字段为scope_sha、receipt_sha、status（pass/issue/uncertain）、task_manual_edits=0和findings（子scope内path、sha256、locator、observation）。此文件是研究者介入证据，不是新的付费审查会话或向用户再次索取许可。再次execute验证该记录后推进；有重大缺陷或专业分歧则不升级为完整通过。开发未通过结束全批，验证位置未通过保留并继续其他独立位置。所有位置的质量结论保持provisional / LLM-proxy。
