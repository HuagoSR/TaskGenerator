# Production MVP 与准入语义

> 状态：`reference`；核对日期：2026-09-15。
> 本文只定义生产和证据边界；当前结果见[项目概要](../../项目概要.md)。

## 1. 当前质量目标

目标不是“能生成文件”，而是可重复制造真实、证据扎根、可解且 rubric 公平的职业任务，并如实报告失败率、成本和人工介入。当前 R10 仍是研究方法，不是已验证的规模化生产服务。

一个候选只有在以下维度分别有证据时，才能获得相应有限结论：

- 候选材料和 DeliverableContract 完整、可打开且隔离；
- 世界记录的 producer、时点、查询范围、版本和 custody 自洽；
- 候选足以完成任务，且不会泄露答案；
- 正式 rubric 可由候选义务独立支持，允许合理替代表达；
- 计算依据可重放，原生文件公式与布局通过检查；
- 冻结行为评测提供有限的真实使用证据。

上述全部成立仍不自动证明专家质量、稳定区分度或 production readiness。

## 2. 证据层级不得混用

| 证据 | 能说明什么 | 不能说明什么 |
|---|---|---|
| 静态/格式准入 | 身份、路径、隔离、文件和确定性检查通过 | 完整职业真实性与可解性 |
| 专业审查 | 对材料、任务和 rubric 的 LLM-proxy/研究者判断 | 人工专家有效性 |
| 有效交付 | Solver 按合同生成可打开文件 | 业务结论正确 |
| 关键职业结果 | 高价值行为在冻结交付中是否可观察 | 完整 rubric 得分或内部思维状态 |
| 正式原子 rubric | 每项独立成果的授权评分 | 自动证明条目无语义重叠 |
| Legacy diagnostic | 旧 rw-task 下的部分分与模型差异线索 | 正式评分、稳定排名或原生文件质量 |

`completed` 只表示固定清单处理结束；`candidate_ready`、`admitted` 和 `production_ready_for_evaluation` 只在对应版本合同内解释。

## 3. Rubric 与计算依据

正式 rubric 是唯一评分权威。每项需要候选可见的义务来源、一个独立可观察成果、满分条件、适用边界、容差和合理替代路径。教师监督、设计意图、计算期望、开发试做和 grader 反馈不能创设新义务。

计算依据记录输入哈希、来源定位、口径、执行、结果、精度和 rubric 关联，并在断网、无凭据、只读候选输入上重放。可复算只证明确定性实现和追溯，不证明专业口径正确。原生 XLSX/DOCX/PDF 的重算与视觉 QA 仍需独立进行。

## 4. 生产与验证边界

- 生产必须报告所有首次位置、准入/失败/未启动、世界数、非重复任务、时间、token、人工介入和技术恢复。
- 同一世界多题不当作独立复验；文件数、rubric 数、token 或耗时不直接代表复杂度。
- 开发与冻结验证分离。冻结后不按 Solver/Judge 结果改题、替换原稿或重抽低分结果。
- 强弱模型分差是辅助证据；单次作答、同源作者/模型或不可靠 grader 都限制解释。
- Legacy grader 高分不能覆盖已确认的公式、格式、事实或职业错误。

## 5. 非目标

当前不自动导出训练集，不启动 SFT/RL，不公开题库，不 promotion、不切换默认模型，也不建设自动评分反馈优化器、通用业务本体或 evidence-graph runtime。GDPval 仅用于 evaluator calibration，其题目、材料、Gold 和模型答案不进入生成输入。

任何新生产或评测必须遵守[运行手册](../operations/pipeline_reconstruction_runbook.md)并获得独立授权。
