## 当前状态：诊断微测接入已离线修复

本轮已实现并通过无模型实际入口夹具。下一步仍仅建议建立新scope后做有限真实验证：

1. 为合成诊断定义正常完成、需上游处理和交给独立复核的可达路径，复用现有工具，不要求虚构生产咨询或试做；正式生产提交门槛保持独立。
2. 启动即持久化消耗，失败、超时和接纳拒绝均纳入父子核对；统一状态、报告与预算依据。
3. 把编辑声明、rubric和时间关系的预期观察映射到夹具、实际可见文件及接纳检查，允许有据无修改和issue/uncertain正常结束。
4. 用实际微测入口驱动工具、快照和接纳，只替换Provider/传输；覆盖完整双会话路径、无法继续、失败计数和答案键隔离。不能只以prepare测试或旧生产控制器测试作为准入。

上述离线检查不重跑封存微测、不增加旧预算，也不直接进入采购或审计生产。真实Agent效果需新的输入/模型/环境/预算绑定scope，宏观结果仅见概要。

## 职业质量持续目标（部分已有工具支持，语义效果待验证）

下一次新 scope 应先验证修正后的诊断专用交接在真实 Agent 下是否可达，再以独立复核检查候选义务追溯、语义原子性、材料时点/来源关系与合理替代路径。2026-09-11 的 legacy rw-task diagnostic 只补充候选交付和旧评分器行为观察，不决定题目难度、模型排名或质量准入。

本轮生产与只读收尾已结束，证据和准入只见概要。后续优先完善现有方法的质量约束，不增加全知调度Agent、评分框架或更多复核层；本节不授权改题或模型调用。

- **语义原子性**：以能否独立正确或遗漏划分成果，区分来源判断、异常识别、量化和行动；不要把多个成果改成同一个0/满分项后称为原子化。综合结论只检查整合逻辑，避免再要求逐项复述而重复计分。

## 2026-09-10 离线质量诊断加固

在不新增角色、生产批次或评分框架的前提下，新增待新scope显式启用的`r10.quality_diagnostics.1`。它把既有质量要求变成可审计输入：编辑声明绑定实际候选题干/合同差异；编译和终审分别逐条记录原子性、替代条件一致性与重叠判断；作者和终审分别对已声明的记录时点与来源关系保存原文、哈希、时区和精度。诊断不产生评分规则，正式`new_rubric.json`仍是唯一评分标准。

离线夹具应验证“内部metadata改动冒充候选改动”、未覆盖的实际差异、满分与替代条款分歧、独立遗漏的成果、缺失时区，以及记录早于其所称事件等反例。程序能拒绝身份、覆盖和显式顺序问题；Agent是否能可靠识别真实专业矛盾仍待受控生产证据，不从离线测试推断。
- **正式rubric一致性**：满分条件、适用条件、容差和替代路径必须能同时解释，不用教师答案决定冲突条款的优先级。所有改变评分含义的修订只在rubric发生并追溯候选义务。
- **记录知识时点**：利用现有文件核查验证记录编制、修改、分发与所述事件的时序；事后补记需要可见版本，不以猜测消除生成矛盾。
- **候选实际编辑效果**：比较最终候选题干、合同和材料；内部映射清理单列，合理无修改允许。保留有自然来源的同事分析，并说明候选仍需核查和作出什么判断。

后续可先用不含本次案例事实的合成夹具检查上述边界；专业语义仍需独立判断。新外部范围另行授权，旧题只读，不按收尾意见修到通过。

## 首版实现与链式复验背景（历史范围）

2026-09-09以来完成候选输入统一、版本2义务追溯、初始依据与实际变更核对、受限计算重放及原生工具微测。其后收集、输出编码和状态推进分别修复；历史失败和后续独立范围不能合并成同版本无干预验证，具体状态与计数见概要。

现已在既有自主工厂上实现独立开发试做向监督/rubric编译提供文件证据，以及候选材料可复算依据。研究目标仍是专业性、实质复杂度、公平评分与持续非重复产出的成本；不要求修复或重跑旧验证批次。文献、推断与适用限制见[调研记录](../research/agent_task_production_harness_20260907.md)。

生产单元保留世界作者和独立挖掘。候选包、生产者意图、监督和运行证据分开；试做者只看候选包，编译者先独立建立要求与依据，再参考本题开发试做成果。作者考点/难点说明只能在可见性边界内作为待核实设计意图，不能补入隐藏事实。程序管理任务/角色/版本、预算和依赖，Agent 请求咨询或返工；无需先引入全知调度 Agent 或通用框架。

计算依据version 2包含实际执行脚本、来源定位与输入哈希、口径、结果、精度、条件及 rubric 关联。一个脚本可以一次产出结构化JSON，多项评分锚点通过JSON Pointer读取，避免为每个标量重复脚本和进程。条目按独立可观察成果拆分，保留合理替代路径，不要求固定数量或候选未被要求的布局/公式。脚本可重放不证明专业口径正确；独立试做也不能成为唯一答案。

首版复用薄控制器，没有迁移SDK、建设企业模拟平台或恢复评分器。2026-09-08两个开发位置经三次绑定续跑仍未完成端到端闭环：采购已形成材料、任务、41分rubric、五组计算依据、两次成功重放和一次有效开发试做，但编译者重复请求试做并耗尽生产额度；审计形成材料后，咨询因继承时钟到期而未被接纳。全链17次启动，无最终提交、终审或最终试做。开发反馈可支持有限修订；最终提交后复核不回流，旧scope终结和隔离规则不变。

上述状态机改进已于2026-09-08离线实现：一个候选上游版本只允许一次开发试做，教师侧rubric或依据调整不使试做失效；角色可查询有效版本、已完成阶段、合法下一动作、缺失前提及精确预算；批次和单题时钟均从首次实际语义启动建立。计算重放改用候选输入只读挂载、独立输出和全次共享时限，重放身份绑定精确编译快照。采购单题复验在材料咨询、修订和独立挖掘后进入编译，但因计算合同不可发现且错误不定位而超时，未完成闭环。

2026-09-09另定的新采购开发scope在降摩擦接口上完成了全闭环：13/16次启动，三次咨询含35条独立finding、47条跨版本处置记录，1个execution承载13个评分数值锚点，两次重放、开发试做、最终提交、独立终审pass和盲试做均完成。rubric为9项33分；上游返工0、任务人工修改0。研究者收尾发现编译者把设计意图/试做中的资金余量计算补成满分要求，候选题干义务不够明确，故完整准入为uncertain；原始XLSX公式也均无缓存，静态错误扫描不能代替重算。该结果是单题provisional / LLM-proxy证据，不计批量通过率，也不证明跨职业迁移。

本轮把计算合同改成结构化version 2，并实现定向schema、draft/ready检查、动作内原子快照、批量处置和动态status。编译`check`降到6次且仅2次失败，但`rubric_basis_not_candidate_visible`仍没有criterion及字段定位，Agent为排障额外咨询；CLI JSON引号及大批量inspect也仍有摩擦。下一版本先补足可见性错误的精确问题列表和更稳健的结构化CLI传参，完成离线验证后再另定冻结的小规模跨场景实验；不再通过增加案例化提示词或复核角色修补接口。

## 已有方法与小批量迁移背景

研究对象是固定方法的持续产出能力，而非修好个别题目或必须分出材料策略胜负。复用业务过程与来源记录、材料物化、独立挖掘、监督/rubric 编译及独立复核；跨职业仅替换准入种子、公开规则和 Professional Skill。具体执行边界见 [Runbook](../operations/pipeline_reconstruction_runbook.md)，实现见 [方法模块](../../src/task_generator/production/task_method_pilot.py)。

前一固定阶段方法周期采用一个采购开发世界形成一次通用修订，再冻结跨场景验证；其方法记录保留，最近已结束的自主工厂批次的冻结时点与逐题试做规则见下文。开发结果与验证位置分开统计，验证失败不替换、具体诊断不进入后续验证输入，验证结论不反向修改该批方法。原生 Agent 试做只诊断实际完成障碍，不评分或比较模型。

质量同时检查事实与来源、职业用途、要求追溯、公平条件路径、实质可解性和自然复杂度。生产能力报告全部首次尝试、失败、耗时、可获得消耗及人工介入；相同配置可复做不等于生成文本逐字确定。即使四个验证位置都通过，也仅为本次小批次初步代理支持。

冻结方法的通用澄清见 [版本化说明](../../data/r10/task_method_clarification_v2.md)：记录知识时点、自然作者与文档用途、剩余专业工作、调整依据和准确引用。实现错误与专业质量问题分开记录；既定复核意见与研究者只读核查有重大分歧时保留不确定，不自动安排该题试做。原始意见不改写。

## 现有实现与旧批次方法

已有有限五位置批次模式，复用自主工厂入口及 [批次模块](../../src/task_generator/production/agent_factory_batch.py)。旧批次要求一个价格开发世界完整通过后，按价格、验收、审计、审计四个位置复验；不是无限生产队列，也不是新方向的执行门槛。职业配置选择已准入种子及其关联规则，Skill原来源ID通过显式映射关联已读取的官方资料；验证摘要与适用限制独立版本化，不覆盖历史职业输入。公开来源只约束方法与记录用途，不能证明合成交易真实发生。

同一方法、工具、角色提示词和三个职业配置在开发题前冻结，验证中不改方法或替换失败位置。单题内自主修订属于被验证的方法，报告“首次最终提交准入”而非“初稿合格率”。开发题及验证题的只读研究者收尾绑定实际receipt和文件证据，属于人工介入，只能保留或降低模型准入结论，不向后续角色泄漏问题或答案。状态、预算和结果见概要与Runbook。

自主工厂采用可修改草稿、容器外版本快照、独立咨询与协作交接。Agent 主动选择检查和修订；控制器仅管理权限、预算及依赖失效。世界、挖掘与编译角色上下文隔离，材料变化后重新挖掘；最终提交只复核一次，不将终审意见回流修题。实现入口为 [自主工厂](../../Test/run_r10_agent_factory_pilot.py) 与 [版本和预算模块](../../src/task_generator/production/agent_factory.py)。原单题入口保留开发可行性检查语义，有限批次入口管理跨场景复验；宏观结果仅见概要。

隔离单位是完整会话输入，包含题目文件、提示词、交接说明、咨询反馈及持久历史。下游角色不接收上游作者的自由交接说明；说明仅保存在运行证据。独立挖掘重新开始，咨询意见只返回绑定快照的原角色；编译者提出的材料问题可返回世界作者，不经其他通道转交给 Miner。实现修复须与真实复验区分，不因离线测试通过就宣布完整闭环已成立。

工具在咨询、交接、提交前反馈当前合同错误，让作者在同轮修正；停止不要求有效产物。检查绑定实际文件哈希，咨询处理通过 `record-disposition` 绑定请求、finding、处理快照和证据，允许接受、部分接受或拒绝。后续修订使旧检查与旧处理快照失效；上游版本已失效的下游咨询不混入新角色。程序验证记录完整性，独立终审判断专业处理是否充分。该实现曾采用替换传输边界的完整控制器夹具演练，再在另定 scope 中复验；不是当前待执行指令。

只读结果角色也须有当轮完成检查，不能仅依赖会话结束后的拒绝。`finish` 对咨询、终审和试做输出执行现有合同检查并绑定哈希；错误返回具体字段，Agent 在当前会话修正输出表达，成功后不得改文件。`schema` 提供单文件引用约定和实际文件清单；多来源分列 finding，不拼接或缩写路径。终审当轮纠正引用格式不等于将终审意见回流给生产者。此补丁的真实验证状态仅见概要，不据离线演练宣布已获外部支持。

评分扩展阶段性暂停，不继续 G2-B 或新建 G2-C，不追加模型 panel、格式证据服务或通用评分框架。评分收尾授权本身不包含后续实验；另获授权的方法周期按独立 scope 执行。

完整评分基线不再是全部造题工作的前置条件。保留逐 rubric、真实文件检查和程序求和作为实验工具；未验证总分不能用于宣布任务难度或强弱区分。GDPval 仅校准 evaluator，具体内容不进入生成或策略选择。

## 历史方向：自产开发题 rubric 要求追溯

离线检查的当前状态、证据和限制只见[项目概要](../../项目概要.md)。方法是先从候选可见要求建立材料与成果对应，再用少量局部案例检查明确要求、替代结论和部分正确组合；发现上游材料或监督问题时单独记录，不用 rubric 补造事实。不得读取 GDPval 内容、历史 Solver 作答或分数作为生成改良输入。

若另定范围采纳修订建议，只派生新版本，不改冻结题目、监督或旧 rubric。条件结论路径须贯穿价格判断和后续建议；全表分值归属须避免同一成果重复计分。局部案例中的分值示例不是已编译的新标准。以已知冲突均有处理、上游不足明确记录为检查结束条件，不将 rubric 绝对完善设为所有造题研究前提。

## 历史方向：World-First / process-first 比较

将 process-first 作为 World-First 内部的材料生成策略：比较直接组织世界材料与先确定业务事件、参与者、记录形成时点及来源关系再生成材料。固定公开种子、规则、模型、工具和预算，保持冻结材料后独立 Task Mining；miner 不读取隐藏过程账本或预期答案。

比较事件是否自然产生记录、任务是否有明确下游用途、跨系统差异是否有业务原因、来源是否相互依赖，以及任务能否仅凭候选材料解决。不以文件数量、文辞丰富或无条件确定结论替代真实性。具体输入、模型、环境和调用预算须在后续计划确定；小样本首先用于发现失败模式，不足以证明方法优劣。

## 保留能力：有限行为评测（非当前执行计划）

只对通过真实性、准确性、可解性和 rubric 检查的任务，使用统一 Stirrup harness 做有限作答与评分。专业条目差距是质量证据之一，不是任务质量的唯一标准。评分有歧义时保留不确定性，必要的独立复核另定预算，不追逐预期排名或自动反馈优化。

## 共同边界

历史结果全部保留；未来规则不得用于改写旧分。新实验分别绑定 scope 与预算，不重抽低分，不训练、部署、公开或自动进入下一阶段。所有专业判断仍为 provisional / LLM-proxy。

## 已知问题形成的设计约束（不启动旧题修复）

候选实际输入应成为要求追溯的直接核对对象：题干、内部要求表、监督和rubric不能互相替代可见义务。按已提供文件核对悬空引用；将更深入但未明确要求的分析保留为等价或可选路径，不能在满分边界暗加方法、重复表达或特定呈现形式。通用工具说明也可按角色最小化，但不以说明中出现其他角色名称直接断言案例数据泄漏。

修订效果按实际差异区分补充记录、纠正事实、修改合成组织政策、保留未决事项和拒绝过强意见；接受标签不是成功证明。核对记录声称的日期范围、时区、筛选与文件实际覆盖，避免以缩小政策义务代替补齐证据而不说明。监督要区分“未提供/未找到证明”与“确定未执行”，同源一致与外部取得链也分别判断。

试做发现新证据条件时，分别检查回答自身缺点、监督遗漏与任务重大缺陷。额外有依据的条件意见不自动判错，未解决的公平性分歧不因一次终审pass被覆盖；这些发现只形成下一版本需求，不建设自动评分反馈或新增通用审查层。

在现有薄控制器和阶段职责内，优先明确每阶段实际可引用的文件，避免用未来题干/合同自我证明挖掘要求；将 Rubric V2 的保留 `decision_id` 与普通专业判断明确区分，不改旧合同。材料自检应对照记录自身声明的快照时点、修订、筛选和派生规则核对实际文件；有业务差异时保留可支持的原因，不能临时补造解释。独立复核须区分同源转录与独立佐证，记录实际核查范围。

这些是方法改进建议，不回流修改已冻结批次。后续如另定实验，继续报告首次合格、阶段输出失败、专业未通过、试做障碍、消耗和运行介入；不以任务级手改为零宣称无人化生产，不以可复做配置宣称已在另一环境复现。宏观证据仅见概要。
