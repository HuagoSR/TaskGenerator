# 下一方向：S1 通用任务制造与可观察质量证据

> 状态：`active / proposed direction`；更新：2026-09-15。
> 本文只描述下一阶段方法，不授权外部运行。宏观证据与停止点以[项目概要](../../项目概要.md)为准。

## 1. 研究目标

验证一套轻量方法能否在不同职业、不同世界重复生成：

- 由自然业务事件产生的多文件材料；
- 明确、可观察且职业上有意义的工作成果；
- 候选材料足以支持、但不会提示答案的任务；
- 可脱离教师答案独立使用的公平原子 rubric；
- 能以有限行为证据检验、且不会把报告措辞误当能力的难度结构。

S1 是优先开发路径，P 只作历史参照。该选择减少编排成本，不改变 World-First、候选/教师隔离、正式 rubric 唯一性或外部实验另定 scope 的边界。

## 2. 通用 S1 生产方法

### 作者输入

作者只接收简短通用生成合同、公开职业触发/规则和一个适用 Professional Skill。不读取旧题、Solver 答案、模型排名、逐案失败清单或 GDPval held-out 内容。

合同要求作者：

1. 先建立独立业务世界和自然记录链，说明 producer、record time、query scope、版本与 custody；
2. 定义清楚的职业成果，必要时覆盖闭集对象或问题集合；
3. 生成候选材料、DeliverableContract、教师监督、原子 rubric 和可重放计算依据；
4. 使用工具与 self-check 修正同一作者会话中的草稿；提交后主控制器不替作者修业务事实或 rubric。

材料数量和格式服从业务需要，不设置固定文件/异常配额。普通任务允许自然冗余；只有受控 A/B 才要求条件证据隔离。

### Rubric 与关键结果

- 每个 rubric item 只对应一个独立可观察成果，权重反映职业重要性，不按固定模板拆分。
- 满分条件、适用条件、容差、证据来源和合理替代表达必须能够同时成立。
- 候选可见义务是唯一要求来源；教师监督、计算锚点、设计意图和试做答案不能增加或收窄义务。
- 冻结的关键职业结果是“高价值成果 → 正式 rubric item → 候选义务/证据”的教师侧映射，用于诊断，不增加分数或呈现要求。
- 上游错误与其机械下游结果避免重复扣分；综合判断只评价真正的整合成果。

## 3. 离线准入

每个首次位置无论成功或失败都保留。准入按以下顺序进行：

1. **身份与隔离**：task ID、题干、DeliverableContract、reference/deliverable 清单、路径与哈希一致；候选侧不含 rubric、锚点、脚本或作者上下文。
2. **全格式结构**：逐行检查 CSV/TSV schema；PDF/DOCX/XLSX/Markdown 可打开、可提取，必要时重算和渲染；公式错误、缓存缺失和视觉问题分别报告。
3. **事实与因果**：日期、实体、金额、数量、版本、生产者和查询范围一致；材料不能声称在其生成时点尚未知的事实。
4. **可解性与公平性**：每个 rubric 要求有候选可见依据，允许职业上合理的条件结论和等价表达；不以教师答案补足缺口。
5. **计算重放**：机械锚点可重算且来源可追溯；重放通过不等于专业口径正确，仍需职业审查。

未通过准入的题不修复后替换首次结果、不进入行为评测，也不为达到预定数量补题。

## 4. 难度与行为测量

优先研究能影响最终职业行为的负担，而非文件数或隐藏数字：

- evidence state 是否被正确识别和维护；
- 实体—属性或来源关系变化是否被局部更新；
- requirement 是否正确映射到 unresolved matter、follow-up 和职业行动；
- 无关状态是否保持不变；
- 计算、总体重建和条件判断是否能在原生交付中一致实现。

观察分为两层：

1. **Evidence-state uptake**：必需证据是否存在/缺失、缺口是否仍 unresolved、follow-up 是否匹配。
2. **Disposition expression**：允许 hold、referral、conditional consideration 等职业上等价表达，除非合同明确规定排他结果。

不要求模型机械复述 tuple、correction chain 或内部推理。若中间状态可被合格交付省略，则标为不可识别，不以沉默判失败。受控实验必须先做全格式 candidate-visible evidence audit；graph depth 与 inference depth 分开定义。

## 5. 有限 rw-task 诊断

只对已冻结且通过准入的候选使用统一 Stirrup/E2B harness。每次评测另建输入、模型、环境和预算绑定 scope，并在调用前验证实际路由、工具闭环、Judge 结构和空输出目录。

- 每个 task/model 使用独立会话；候选输入完全相同，顺序离线冻结。
- 先验收原生交付，再核对关键职业结果；无效交付不进入语义评分。
- Legacy grader 的 `score=max_points` 视图只作兼容，原正式 rubric 不改。部分整数分和高分复审必须标为 diagnostic。
- 原生文件 QA 与 grader 分数并列保留；grader 高分不能覆盖 XLSX 公式、DOCX/XLSX 可读性或候选事实错误。
- 单次分差只提供案例证据，不建立稳定模型排名、区分率或 production promotion。

评分器扩展不是当前重点。若 legacy 诊断与文件 QA 冲突，优先记录测量限制，而不是建设新的通用评分框架。

## 6. 下一批建议

1. 继续小批跨职业首次生产，每批固定少量位置，不因失败自动补位。
2. 在作者合同不膨胀的前提下，加强表格 schema、公式和 source-causality self-check。
3. 准入后冻结 rubric—关键结果映射，再选择少量不同能力模型作一次隔离诊断。
4. 跨任务比较反复出现的失败机制；只把多案例支持的规则写回通用合同或 Skill。
5. 同时报告合格题、失败题、时间、token、人工介入和技术恢复，避免只展示成功样本。

## 7. 非目标与停止边界

- 不围绕 G1/G2 或其他单题持续修补以追求漂亮结果。
- 不从任务文件数、token、耗时或一次共同失败直接推断难度。
- 不新增业务本体、证据图执行器、自动 grader 反馈环或额外角色层。
- 不自动开启模型调用、扩题、训练、部署、发布或 push；任何外部运行仍按[运行手册](../operations/pipeline_reconstruction_runbook.md)另定 scope。
