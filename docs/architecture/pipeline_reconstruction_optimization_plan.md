# R10 活跃计划：评分经验回流 Rubric 生成

> 状态：active；宏观证据见 [项目概要](../../项目概要.md)。

## 目标

结束大规模 evaluator 排名验证，把三题独立评分暴露的要求错位、范围漏检和表达歧义转为任务编译方法。GDPval 具体内容不进入生成链。

## 实施顺序

1. 文档收尾并提交，记录精简评分 12/12 与探索性证据。
2. 新增 TaskSpecificRubricV2，复用现有编译器和远端执行；一个判断允许多个条目，不设固定条目数或拆分比例。
3. 每项描述要求、分值、得分边界、要求依据和核验方式；独立审查隐藏义务、重复计分、证据、例外及等价表达。
4. 仅处理 R10.9 audit reliability baseline 与 procurement price baseline。原题干、candidate、Teacher Truth、矩阵、旧 rubric 和答案不变。
5. Terra medium 生成两次，官方 DeepSeek V4 Pro max 审查两次；全批最多两次格式/传输补跑，不因内容不理想重抽。
6. 提供中文“工作要求 → 评分项 → 得分边界 → 依据与核验方式”，更新结果并提交后停止。

## 编译原则

- 要求来自题干或候选可获得的专业依据，不来自隐藏答案偏好。
- 一项评价一个可观察成果，共享材料不等于重复计分。
- 条件未触发、题干例外和合理替代方案必须写清。
- 逐月/逐条/全部等范围必须完整核验，无法检查就记录不完整。
- 不凭章节名、标点或风格暗扣分，不增加整体偏好或重大错误总分否决。
- Agent 处理专业语义，程序只检查结构、引用、计分和隔离。

## 验收与后续

定向测试、完整回归、diff 与 secret scan 通过。负例使用合成材料，不将 GDPval 内容做成生成提示。历史 V1 和 evaluator 合同保持兼容。

本轮不访问留出题进行调参，不运行 Solver、评分、旧 60 次队列或十题生产。审查失败保留问题；未检查实际新答案，不宣称评分稳定。用户查看两份结果后再决定是否恢复造题实验。
