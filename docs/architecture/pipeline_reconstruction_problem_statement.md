# TaskGenerator 真实性重构问题定义

> 状态：`active`
> 职责：定义 R10 要解决的研究问题；不替代《项目概要》的状态记录，也不规定实现细节。

## 结论

当前系统能够稳定地生成结构完整、可渲染、可导出且可执行的任务包，却不能稳定地产生类似真实职业工作现场的“大任务”。问题不在于某道题的字段或某个模型，而在于生成起点、事实表示和验收目标共同把系统推向最小可验证案例。

R10 的核心问题是：如何从公开、可追溯的职业工作原型和专业规则出发，自动构造自洽业务世界，并将其投影为可解、不可投机、可评分的多文件职业任务。

## 已确认的证据

- R9 证明服务器发布、任务包物化、交付合同和三模型执行可以形成可审计闭环。
- R7 从零复验重新采集来源、提取 skills、编译 briefs 和生成十题，但 task-design provider 不稳定使其冻结为 5/10；这不是任务真实性的正面或反面证据。
- 五道已物化任务的目测显示：来源边界、文件打开性、业务字段和关系连接良好；但每表通常仅三至四条记录，异常常以状态字段表达，业务时间线、正常背景和具体决策后果不足。

## 为什么当前任务不够真实

### 专业规范不等于工作现场

PCAOB、FAR 等来源说明应如何判断，却不说明一个组织为何在特定时间产生某些记录、不同部门如何记录同一事件，或经理为何现在需要一个工作底稿。来源可证明方法论边界，不能单独生成职业情景。

### Skill 抽象丢失了情景因果

“评估证据可靠性”或“核对发票完整性”描述能力，却不包含触发事件、角色、时间线、信息来源和决策后果。以 Skill 和 capability 直接生成任务时，LLM 会自然生成最典型、最短、最容易满足合同的案例。

### Motif-first 反转了真实工作的形成顺序

`cross-check`、`fan-in` 和 `policy-application` 描述信息关系形状，不解释文件为何存在。先选 motif 再填业务故事易产生“为关联而关联”的表格。真实顺序应是业务事件产生记录，记录之间自然出现多个 motif。

### 输入与真值同时设计导致答案泄漏

当同一 proposal 同时创造情景、文件和异常，最容易的可解性保证是把结论写进输入，例如 `Questionable Support` 或 `Requires Follow-Up`。候选应看到的是事实冲突、证据缺失和时间差，而不是最终专业判断。

### 确定性门禁优化了可验证性

现有门禁擅长检查 schema、主键、连接、文件打开性、provenance 和导出一致性。它们不能充分检查业务因果、组织语境、真实工作量或专业判断质量。若将文件数、字段、对象和投影映射继续升级为硬合同，生成器只会改为满足更复杂的结构目标，而不一定更真实。

### 旧 Skill 既过于抽象，也承担了过多职责

旧 Registry 中的 Skill 保留了来源、业务意义和失败模式，但也携带了输入输出语义图、交付物和任务装配提示。后者使 Skill 在没有真实工作事件时提前决定任务形态。专业知识应以可按需加载的 Agent Skill 提供，业务故事必须仍由 Work Seed 与 Scenario Bible 产生。

### 通用 rubric 压平任务差异

七维 rubric 能评估成果的一般质量，却不能替代每题的关键业务结论。缺少题目级 decision matrix 时，外观完整、引用充分的工作簿可能掩盖错误的专业处理，并导致评分饱和。

## R10 研究假设

如果先构造 teacher-only 的业务世界，再由出题 Agent 在少量专业 Skill 的帮助下生成带来源和父 Bible 追溯的证据包，并以 task-specific 决策矩阵定义真值和评分，那么任务将同时改善：

- 因果真实性：文件由同一事件和时间线自然产生；
- 信息真实性：冲突与缺口表现为事实而非答案标签；
- 职业真实性：角色、触发、受众和交付物具有业务理由；
- 评测真实性：模型差异来自判断与交付质量，而非路径或格式偶然性。

R10.8 表明“先写 Bible，再围绕已知判断生成紧凑证据”仍可能使任务围绕答案组织：题干容易枚举应做分析，材料缺少独立业务生命周期，结果要么评分饱和，要么把不稳定的 Judge 边界误认为模型差异。

R10.9 的新假设是：先生成没有题干和 rubric 的完整工作世界，冻结自然业务材料，再由独立 Task Miner 发现工作任务，并让另一 Agent 从可见证据重建真值；同时用来源约束的职业对抗难度提高判断张力。这样才可能同时获得真实感、考试强度和可解释区分度。对抗难度必须改变业务事实和证据关系，不能增加乱码、格式摩擦或无依据陷阱。

R10.9 的实际结果说明，World-First 已能稳定产生可挖掘、可解且可交付的工作任务，但“容易辨认三档合成样本”并不等于“能稳定裁决真实灰区交付”。两位 Judge 均通过校准，却在四题正式 paired review 中全部产生偏好或重大错误边界歧义。因此当前最先需要解决的是 evaluator 对证据引用、重大错误和部分满足边界的可重复性，而不是继续提高题目难度或扩大题量。

## 非目标

- 不把 GDPval 内容或 hidden rubric 用作生成材料。
- 不将 LLM proxy 或静态检查解释为人工专家有效性。
- 不以增加噪声、乱码或不可见信息制造难度。
- 不因单个模型低分而修改已冻结任务或进行选择性重抽。
